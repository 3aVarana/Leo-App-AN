## Android decisions

- **D1 Ownership.** iOS: one long-lived `QuizViewModel` owned by `RootViewModel`. (a, recommended) `QuizViewModel : ViewModel` in the Activity store (`MainActivity` factory, key "quiz"), passed to `RootViewModel(…, quiz)`; same lifetime, survives rotation, cleared (generation cancelled) when the Activity finishes. (b) plain class on root's scope: deviates from the mapping table. Ctor: `(makeRepository: (RoundSettings) -> ExerciseRepository, now: () -> Instant = Instant::now, random: Random = Random.Default, onRoundFinished: (RoundRecord) -> Unit = {})`.
- **D2 State and coroutines.** Private queue/exercises/failedJobs/plan as in iOS; one `publish()` rebuilds `StateFlow<QuizUiState>` after every public call and generation step; derived values (`optionState(i)`, `dotState(i)`, `correctCount`, `misses`, `isLastExercise`, `readingTime`, `isAnswerCorrect`) are members of `QuizUiState`. Generation = `viewModelScope.launch`, job recorded before it runs (phase-5 D3 lesson, `CoroutineStart.LAZY`); `generationNumber` kept. After `exercise()` returns, drop the result if `!isActive`. A `CancellationException` while our job is still active is treated as a failure (phase-5 hardening; iOS ends the loop, `:254`): Q1. Logging `Log.e("QuizViewModel", …)`, so VM tests run under Robolectric. `QuizScreen` uses `AnimatedContent(targetState = state, contentKey = { it.phase })`, so a fading-out phase keeps its own state (Crossfade on `phase` would draw Exercise with a null exercise).
- **D3 Reading timer.** iOS keeps it in the view, not the VM. (a, recommended) Same here: `ReadingTimer` composable, `remaining` in `rememberSaveable` keyed by `exercise.id` (survives rotation), countdown `LaunchedEffect` inside `repeatOnLifecycle(RESUMED)` of the back-stack entry (iOS `scenePhase == .active`): `delay(1000)` steps, partial seconds lost on pause exactly as iOS. Tested with the Compose `mainClock` (`autoAdvance = false`, `advanceTimeBy`) and a `TestLifecycleOwner`. Snapshots pause the clock so the time can't tick. (b) timer in the VM with injected time: testable with `runTest`, but adds state iOS doesn't have. Display m:ss via `String.format(locale, "%d:%02d")`; TalkBack value via ICU `MeasureFormat` WIDE.
- **D4 TalkBack.** `rememberTalkBackOn()` = `AccessibilityManager.isTouchExplorationEnabled` with a state-change listener, `LocalTalkBackOn` override for tests; the timer is removed while it is on (phase-5 Q1). Question focus: `FocusRequester` on the focusable question heading after read->question (device check). Loading announcement: `liveRegion = Polite` on the merged heading (`announceForAccessibility` is deprecated). Result-row hint "Review": `onClick(label = "Review")`. Option value: `stateDescription`.
- **D5 Navigation.** Quiz phases stay inside `LeoRoute.Home` (iOS: root content, no back button). New `LeoRoute.Review(startIndex: Int)` pushed from Results (`dropUnlessResumed`); misses read from `quiz.uiState`; if they are empty (process death restored the route) it pops at once. Gear -> `LeoRoute.Settings`. Pager = `HorizontalPager` (Compose foundation), `animateScrollToPage`, plain scroll under reduced motion. System back on Home: no `BackHandler` (parity: iOS has no way out of a round); on API 31+ back moves the task to the background and keeps the round; on API 29-30 it finishes the Activity and the round is lost (Gemini Nano devices are Android 14+). Review top bar: Q4.
- **D6 Saving rounds.** iOS `onRoundFinished -> history.record` (`RoundHistoryViewModel`, phase 7). Here `RoundHistoryRecorder(repository, scope).record(round)` launches `save` on `AppContainer.applicationScope` (`SupervisorJob() + Dispatchers.Main`), catching and logging like `RoundHistoryViewModel.swift:89-95`; application scope so a save started at "See results" survives the Activity finishing. Phase 7 folds it into `RoundHistoryViewModel.record`.
- **D7 Background inference.** ML Kit GenAI refuses inference from a background app (`BACKGROUND_USE_BLOCKED`; verify on device). Generation running while the reader is in another app would then fail every topic and burn replacements. Recommend: `QuizViewModel.pause()` on Activity ON_STOP (cancels the generation, keeps the queue head; not a failure) and `resume()` on ON_START (`generateRemaining()` if the queue is non-empty), from `RootScreen`'s `LifecycleEventEffect`. Q2.
- **D8 Motion and haptics.** Haptic `HapticFeedbackType.Confirm`/`Reject` keyed on `isAnswerCorrect`; shake = `Animatable` + `graphicsLayer.translationX`, skipped under `rememberReduceMotion()`; scroll to feedback uses `animateScrollTo` unless reduced motion; phase and read->question fades stay (Compose scales them to 0 under "Remove animations"). Timer bar `animateFloatAsState(tween(1000, LinearEasing))`.
- **D9 Formatting.** Spelled-out count: ICU `RuleBasedNumberFormat(locale, SPELLOUT)`, first letter uppercased in the locale; topic list: ICU `ListFormatter`; process-death loss of an unfinished round accepted (VM state only, like iOS app termination). Passage `SelectionContainer`.
- **D10 History button.** iOS hides it until a round is saved (`RootView.swift:100-102`); `hasRounds` comes from phase 7: Q3.

## Acceptance criteria
1. A prepared round starts generating before Start; Welcome names its topics; Start shows Loading or the first ready exercise.
2. Passage first, question after "Answer the question" or when the timer ends; the timer starts full per exercise, pauses in the background, survives rotation, and is absent when off in Settings or with TalkBack on.
3. Option states, verdict, explanation, shake (not under Remove animations), haptic, "Next text"/"See results" match "Behavior to preserve".
4. A failed exercise is replaced with the same skill, at most 3 times per round; afterwards Failed shows with both retries; earlier answers are kept.
5. Finishing saves exactly one `RoundRecord` to Room (double tap included); Results and Review show the finished round even after Settings changes; "Practice again" starts a new round of the current size.
6. All ported Quiz/Plan/Root tests and the Android-only tests pass; snapshot suites recorded, every image opened and compared with iOS, nothing clipped at 200%.
7. TalkBack: headings, Loading announcement, option values, row actions, timer node, question focus checked on device (or left for the user).
8. Strings in `values/`, `values-es/`, `values-pt-rBR/`; `HomePlaceholder` deleted; no ML Kit/Room import under `features/`; `./gradlew assembleDebug`, `./gradlew :domain:test testDebugUnitTest`, `./gradlew detekt ktlintCheck lintDebug` pass.
9. `changes.md` lists D1-D10 and the answers to Q1-Q5; `docs/learning/phase-6.md` written.

## Decisions (user, 2026-11-03)
- Q1: a `CancellationException` thrown by the repository while the round's generation job is still active **counts as a failed exercise** (phase-5 hardening). Only our own cancellation (`!isActive`) ends the loop.
- Q2: **pause and resume.** `pause()` on Activity ON_STOP cancels the current generation without counting a failure and keeps the queue head; `resume()` on ON_START continues `generateRemaining()`. Verify `BACKGROUND_USE_BLOCKED` on device.
- Q3: **History button hidden** in phase 6; `hasRounds` and `homeNavigatesToHistoryAndBackPops` move to phase 7.
- Q4: Review top bar = **back arrow + "Results"** (iOS back title) on the left, "%d of %d missed" caption on the right.
- Q5: **plain strings**, not `<plurals>`, for `quiz_topics_more` and `review_count`: iOS parity, one string per locale.
- Plan approved as written otherwise; D1-D10 stand with the recommended options.
- Review B2 (user, 2026-11-03): **keep iOS behavior.** `configure` re-prepares the round when settings differ, even mid-round after a device-language change. Not fixed; documented in `changes.md` as a known Android-only glitch.
