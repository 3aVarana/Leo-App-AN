## Android-only deviations from iOS

- **Plurals** for the three count strings (iOS: plain strings, so es/pt-BR read "Repasar 1 falladas"). English unchanged. Offer the same catalog fix to iOS separately.
- **Formatting locale**: language from the resources, region and Android 14 regional preferences from the device, like `Locale.current`. On a French phone, English words get English "and" without a serial comma and "15 Jan, 12:00" (en-FR, like en-GB), never French. `Kicker` now uppercases in this locale too (it used the configuration's: a Turkish phone would have dotted the I of English).
- **First weekday** comes from `localeFirstDayOfWeek(deviceLocale(application))`, passed by the `MainActivity` factory, instead of `Locale.getDefault()` (the plan said to leave it): with a per-app language the JVM default and the process configuration lose the region, and the first weekday must follow the region, as on iOS (review S1).
- **Per-app language** on API 33+ (en, es, pt-BR). API 29-32 follow the system language (AppCompat's backport isn't approved).
- **Debug stub model** and the **adaptive icon** (above).
- **Snapshot names**: `highContrast = true` does not add `-highContrast` to the file name (the plan said it would; it would have renamed the existing `ThemeSnapshotTests/colors-highContrast`, which already carries the word). The new suite names include it.
- **Settings stays a full-screen route on tablets** (Q6), where iOS shows a form sheet.
