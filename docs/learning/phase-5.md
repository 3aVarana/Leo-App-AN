# Phase 5: preferences

**ViewModel scoped to a back-stack entry (iOS: the sheet's `@State` editor).** Inside a `composable<Route>` block, `viewModel()` stores the ViewModel in that destination's `NavBackStackEntry`. So each time Settings opens it gets a new editor built from the current preferences. Popping the entry (Cancel, Done, Back) clears the ViewModel, and `viewModelScope` cancels any pending review, which plays the role of the iOS editor's deinit. The onboarding gate isn't a destination, so its editor lives in the Activity's store and survives rotation. That is why `save()` cancels the review itself (`LeoNavHost.kt`, `RootScreen.kt`, `PreferencesEditorViewModel.kt`).

**Nested `NavHost` (iOS: a `NavigationStack` inside `OnboardingView`).** Onboarding has its own `rememberNavController()` with two `@Serializable` routes, so system and predictive Back pop from Topics to the age picker with no code (`OnboardingScreen.kt`, `OnboardingRoute.kt`). A route is a typed argument bag that survives process death, and Android can kill a backgrounded app at any time. That's why `Topics` carries the picked age group. It is stored as a raw string, because an enum route argument needs `@Keep`, which pure `:domain` can't use.

**Taps during transitions (iOS: no equivalent).** A screen sliding out still takes taps, and `navigate`/`popBackStack` run on every one, so a double tap pushes twice or pops Home too. `dropUnlessResumed { }` ignores the tap unless the entry is `RESUMED`. It must be created inside the destination so it reads that entry's lifecycle (`LeoNavHost.kt`).

**Text field state in the ViewModel (iOS: `var newTopic` on an `@Observable`).** A `TextField`'s value has to update synchronously. Passing it through a `StateFlow` and back a frame later can lose IME edits, so `newTopic` is a Compose `mutableStateOf` in the ViewModel and everything else stays in `StateFlow<UiState>` (`PreferencesEditorViewModel.kt:102`).

**Cancellation (iOS: `Task` + `Task.isCancelled`).** The review is a `viewModelScope.launch`. After it suspends, the code checks `ensureActive()`, and it rethrows `CancellationException` instead of treating it as an error. The job starts `CoroutineStart.LAZY` and is stored before it runs: a repository that returns without suspending would otherwise finish before `reviewJob` is assigned (`PreferencesEditorViewModel.kt:220`). The test for this runs on `UnconfinedTestDispatcher`, because `StandardTestDispatcher` queues the job and hides the bug.

**Semantics instead of accessibility traits and hints (iOS: `.accessibilityAdjustableAction`, `.accessibilityHint`).** TalkBack has no hints, so the minimum-topics hint is appended to the chip's description. An adjustable control is one node with `stateDescription`, `progressBarRangeInfo` and `setProgress`, which TalkBack adjusts with volume keys or swipes (`TextsPerRoundStepper.kt`). The review spinner is `ProgressBarRangeInfo.Indeterminate`, so TalkBack reads it as busy (`TopicsEditor.kt:211`).

**One-shot effects across recreation (iOS: `.sensoryFeedback(trigger:)`).** `LaunchedEffect(key)` runs again when the composable comes back after rotation, so the haptic compares `minimumWarningCount` with the last count it played, kept in `rememberSaveable` (`TopicsEditor.kt`).
