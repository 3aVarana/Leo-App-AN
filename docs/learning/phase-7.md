# Phase 7: history

**`SwipeToDismissBox` instead of `.swipeActions` (iOS: a `List` row with a revealed "Delete" button).** Material 3 gives a drag with a background and a dismissed state, not a button you can tap halfway. A full swipe from the end deletes at once (iOS's full swipe does too); `enableDismissFromStartToEnd = false` leaves no anchor for the other direction. TalkBack can't swipe a row, so the row also offers "Delete" as a custom accessibility action, which is how VoiceOver exposes swipe actions on iOS. The swipe state is remembered per row key: delete in `onDismiss`, then `snapTo(Settled)`, or a row that comes back after a failed delete returns already dismissed and deletes itself again (review B1; `HistoryScreen.kt`, `SwipeToDelete` and `HistoryRow`).

**`LazyColumn` with `stickyHeader` instead of `List` with `Section` (iOS: `.listStyle(.plain)` pins section headers by itself).** You emit the items yourself: a header item, then per section a `stickyHeader` and its rounds, each with a stable `key`. Keys are saved with the list state, so they must be Bundle-friendly: the section key is a string, not the `Kind` object. A sticky header has no background of its own, so the ground is drawn behind it (`HistoryScreen.kt`).

**`java.time` for weeks (iOS: `Calendar.dateInterval(of: .weekOfYear)`).** The week start is `today.with(previousOrSame(firstDayOfWeek))` at local midnight, and the next boundary is `plusWeeks(1)` on a `ZonedDateTime`, so a week with a clock change still ends at midnight. A month is a `YearMonth`, which has no time zone, so the iOS bug that `monthName` had to work around (a month's first day slipping into the month before west of UTC) can't happen. The first weekday comes from ICU's `Calendar` for the locale, which honors Android 14's "First day of week" setting (`RoundHistoryViewModel.sections`, `HistoryFormatting.kt`).

**ICU skeletons for dates (iOS: `Date.FormatStyle` with `.day().month(.abbreviated)`).** Both ends resolve a skeleton against CLDR for the locale. On Android you ask ICU for it yourself (`DateFormat.getInstanceForSkeleton`), and the 12 or 24 hour clock is not part of the locale: you read it from `DateFormat.is24HourFormat(context)` and pick `hm` or `Hm` (`HistoryFormatting.kt`).

**Load, then navigate, with type-safe routes (iOS: `navigationDestination(item:)` pushes a value it already holds).** A route can only carry simple arguments, so the round travels as its id. A tap launches `history.open(id)`, which loads the round and keeps it in the ViewModel, and navigates only if it loaded and the entry is still resumed. The round page reads it from there; if the process died and the route was restored, it loads the round by id again and pops when it can't, so there is never a blank screen (`HistoryDestinations.kt`, `RoundHistoryViewModel.open`).

**An effect that must outlive its screen (iOS: `.task(id:)` on the root's content, which is always there).** The `LaunchedEffect(preferences)` that tells the quiz and the history about the preferences used to sit inside the Home destination. A restored History has no Home composed under it, so the effect moved above the `NavHost` (`LeoNavHost.kt`).

**Recompute on resume (iOS: `sections` is a computed property, re-read every time History draws).** The Android ViewModel lives as long as the Activity and publishes sections with its state, so a round from Sunday would still say "This week" on Monday. `LifecycleResumeEffect` in the History destination calls `refreshCalendar()`, which rebuilds sections with the current clock, zone and first weekday, without touching the store (`HistoryDestinations.kt`).

**Application scope again, now for writes (iOS: `Task` in `RoundHistoryViewModel.record`).** `record` and `delete` launch on a `storeScope` given to the constructor (the application's in the app), not on `viewModelScope`, so leaving the app right after finishing a round or swiping can't lose the write, and the reload after it is a no-op if the ViewModel is gone. Loads, in contrast, are on `viewModelScope`: a new load cancels the old one, and an answer for another age group is dropped (`RoundHistoryViewModel.kt`, `MainActivity.kt`).

**Optimistic delete (iOS: `try repository.delete` then `reload()`, both synchronous).** The store is asynchronous here, so a swiped row would bounce back while it answers. The row leaves the state at once, with `isLoaded = false` so deleting the last round doesn't close History before the store answers; the reload afterwards confirms it, or puts it back if the delete failed (`RoundHistoryViewModel.delete`).
