# Phase 2: Storage, iOS → Android

**`UserDefaults` → Preferences DataStore.** `UserDefaults` is a synchronous, in-memory cached plist. DataStore is an async key-value file (`files/datastore/leo.preferences_pb`) read through a `Flow` and written with `edit { }`, so it never blocks the main thread. [DataStorePreferencesRepository.kt](../../app/src/main/java/com/victorarana/leo/data/datastore/DataStorePreferencesRepository.kt) keeps the iOS shape: one `stringPreferencesKey("readerPreferences")` holding the same JSON text. Two rules iOS doesn't have: only **one** DataStore instance may exist per file in a process (a second one throws), so `create()` is called once from the composition root; and a damaged file surfaces as `CorruptionException` unless you install a `ReplaceFileCorruptionHandler`.

**Sync repository calls → `suspend`.** iOS reads storage synchronously on the main actor. Android's `StrictMode` and Room both treat main-thread disk I/O as a bug (Room throws), so both interfaces in [repositories/](../../app/src/main/java/com/victorarana/leo/data/repositories/) are `suspend`. The caller (a ViewModel, from phase 4) runs them in `viewModelScope`; the repository moves the work onto an injected `ioDispatcher`, so tests can pass a `StandardTestDispatcher` instead of `Dispatchers.IO`.

**SwiftData `@Model` → Room `@Entity` + `@Dao` + `@Database`.** SwiftData infers the schema from the model class and writes queries for you with `#Predicate`. Room is SQLite with compile-time checks: [StoredRound.kt](../../app/src/main/java/com/victorarana/leo/data/room/StoredRound.kt) and [StoredAnswer.kt](../../app/src/main/java/com/victorarana/leo/data/room/StoredAnswer.kt) are tables, [RoundHistoryDao.kt](../../app/src/main/java/com/victorarana/leo/data/room/RoundHistoryDao.kt) holds SQL that the KSP compiler validates at build time, and a relationship is a foreign key (`onDelete = CASCADE`) plus `@Relation` instead of `@Relationship(deleteRule: .cascade)`. Types SQLite can't store (UUID, `Instant`, lists) need `@TypeConverter`s ([RoundHistoryConverters.kt](../../app/src/main/java/com/victorarana/leo/data/room/RoundHistoryConverters.kt)).

**`@Attribute(.unique)` upsert → an explicit `@Transaction`.** SwiftData replaces a model with the same unique id. Room's `OnConflictStrategy.REPLACE` does a hidden delete that doesn't reliably cascade to child rows, so `replaceRound` deletes by id then inserts the round and its answers in one transaction.

**`VersionedSchema` + `SchemaMigrationPlan` → `version` + exported JSON + `Migration`.** [RoundHistoryDatabase.kt](../../app/src/main/java/com/victorarana/leo/data/room/RoundHistoryDatabase.kt) is `version = 1` with `exportSchema = true`: the `room` Gradle plugin writes `app/schemas/.../1.json`, which is committed like a golden file. Once a build ships, every schema change bumps the version and adds a `Migration(n, n+1)`; without one, Room refuses to open the file (it never guesses, unlike SwiftData's lightweight migration). [RoundHistorySchemaTests.kt](../../app/src/test/java/com/victorarana/leo/data/room/RoundHistorySchemaTests.kt) pins the schema's identity hash so an unversioned change fails a test.

**Store open failure.** `ModelContainer(...)` throws at init, so iOS falls back to memory right there. Room opens lazily on the first query, so [RoomRoundHistoryRepository.kt](../../app/src/main/java/com/victorarana/leo/data/room/RoomRoundHistoryRepository.kt) opens explicitly on first use and falls back then. Android's SQLite also *deletes* a corrupt database file by default; [KeepDamagedFileFactory.kt](../../app/src/main/java/com/victorarana/leo/data/room/KeepDamagedFileFactory.kt) turns that into an error so the file is kept, as on iOS.

**Robolectric for storage tests.** Room and `android.util.Log` need Android classes. Robolectric runs them on the JVM (no emulator); Room tests use `Room.inMemoryDatabaseBuilder` or a file in a JUnit `TemporaryFolder`, the counterpart of the iOS in-memory `ModelConfiguration`.
